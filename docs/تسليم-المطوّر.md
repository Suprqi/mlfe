## ١) ما هو المنتج

تطبيق يبني **ملف إنجاز المعلّم** تلقائيًا. المعلّم يصوّر شواهد عمله طوال الفصل ويربط كلًا منها بسجله، والتطبيق يولّد ملفًا كامل التنسيق جاهزًا للطباعة على A4: غلاف، فهرس، مقدمة، تعريف، صفحات العناصر والشواهد، تأمل ختامي، وملحق تفصيلي — بترقيم تلقائي.

المرجعية: **عناصر تقييم الأداء الوظيفي الأحد عشر وأوزانها النسبية**، ومجموعها 100٪ بالضبط. تحتها **45 سجلًا مرجعيًا** بمسميات متعارف عليها ميدانيًا (مؤكَّدة من معلّم ميداني).

**النموذج التجاري:** 100 ريال سنويًا للأفراد، مع تجربة مجانية.

## ٣) البنية التقنية

- ملف HTML واحد، **1,317,208 بايت**، **6,122 سطرًا**

## ٤) الحالة والتخزين

كائن عام واحد اسمه `S` فيه **85 مفتاحًا**، يُسلسل JSON ويُحفظ في:

```
localStorage['malaffi_state_v1']
```

- حفظ تلقائي كل 4 ثوانٍ + عند `beforeunload` + عند `visibilitychange`
- الصور تُصغَّر عبر canvas (1600px، جودة 0.82) ثم تُخزَّن **data URLs** داخل نفس المفتاح

### أهم البُنى

```js
S.standards = [{
  t: 'اسم العنصر',
  d: 'أمثلة تحقق العنصر',
  ex: ['السجل 1', 'السجل 2', ...],   // 45 سجلًا موزّعة على 11 عنصرًا
  w: 10,                              // الوزن النسبي
  subDone: [],                        // مربعات ✓ للسجلات
  ev: [{                              // الشواهد
    title, type, date, note, result, reflection,
    record,                           // السجل الذي ينتمي إليه — يُستخدم في تجميع الصفحات
    img,                              // data URL
    link
  }]
}]

S.profile = { intro, bio, vision, goals, closing }
```

## ٥) مصادر الحقيقة الوحيدة — لا تكرّرها

| الثابت / الدالة | الدور |
|---|---|
| `PF_STD_W` | الأوزان الرسمية للعناصر الـ11 — **مجموعها 100** |
| `PF_STD_EX` | الـ45 سجلًا المرجعية لكل عنصر |
| `PF_STD_ALIAS` | ترحيل المسميات القديمة → الرسمية |
| `stdWeight(std)` | **الدالة الوحيدة** لقراءة وزن أي عنصر |
| `migrateStandards()` | ترحيل الحالة المحفوظة عند الإقلاع |
| `generateAchievement()` | مولّد ملف الإنجاز بالكامل |
| `computeReadiness()` | مؤشر الرئيسية (30٪ ملف شخصي + 70٪ تغطية موزونة) |
| `computeExcellence()` | مؤشر التميز (15 + تغطية×65 + عمق×20) |
| `evalPct(scores)` | نسبة تقييم المدير للمعلّم — **موزونة** |

**قاعدة:** أي مقياس اكتمال جديد يجب أن يمرّ عبر `stdWeight`. سبق أن ظهر في التطبيق ثلاثة أرقام مختلفة للاكتمال لأن أحد المقاييس كان يحسب بالعدد لا بالوزن — وقد صُحّح.

## ٦) مولّد الملف — كيف يعمل

1. يجمع شواهد كل عنصر حسب `record` (السجل)
2. يحسب **أرقام الصفحات مسبقًا** ليكون الفهرس مطابقًا مهما تغيّر عدد الشواهد
3. صفحة الشاهد **تتّسع** حسب عدد شواهد السجل:
   - 1 → صفحة كاملة · 2 → فوق/تحت · 3–4 → شبكة 2×2 · 5–6 → شبكة 2×3
   - السقف 6 في الصفحة (`pfPerPage()`) حفاظًا على وضوح الطباعة
4. ست هويات لونية عبر متغيّرات CSS — `data-pf` على `#ach-doc`

## ٧) قيود ومخاطر معروفة

1. **التخزين محلي بالكامل** — لا حساب ولا مزامنة. مسح بيانات المتصفح = ضياع كل شيء. حصة `localStorage` ≈ 5MB وقد تمتلئ مع كثرة الصور (يظهر تحذير للمستخدم عند الامتلاء).
2. **مفتاح Anthropic يُستدعى من المتصفح مباشرة** — مقبول في النموذج الأولي، **غير صالح للإنتاج**.
3. **استعلامات الحاويات** تتطلب Chrome 105+. يوجد بديل آمن عبر `@supports not (container-type:...)` يتحوّل لتدفّق مقروء على الأجهزة القديمة.
4. **تصدير Word لا ينقل التصميم** (الموجة وSVG واستعلامات الحاويات). **المخرَج المعتمد هو الطباعة/PDF.**
5. **بيانات قاصرين** — التطبيق يخزّن أسماء طلاب ودرجاتهم. عند نقلها لخادم تنطبق التزامات نظام حماية البيانات الشخصية: مكان الاستضافة، ومدة الاحتفاظ، وسياسة الخصوصية.

## ٩) قواعد تعديل تحفظ الملف من الانهيار

هذه ليست نصائح عامة — كلها أخطاء وقعت فعلًا وصُحّحت:

1. **لا تُنشئ ثابتًا في أعلى الملف يستعمل ثابتًا يُعرَّف بعده.** سبق أن أسقط هذا التطبيق بالكامل (`Cannot access 'STORAGE_KEY' before initialization`). استعمل دالة بدل ثابت.
2. **`esc()` يجب أن يهرّب `& < > " '`** — تُستعمل في 301 موضعًا، منها 42 داخل خصائص HTML. إسقاط علامات الاقتباس يكسر الواجهة عند أول عنوان فيه `"`.
3. **`$()` هي `getElementById` فقط** — لا تمرّر لها محدّد CSS.
4. **مجموع `PF_STD_W` يجب أن يبقى 100.** إضافة عنصر ثاني عشر تكسر كل المقاييس.
5. **مقاسات الملف المولَّد بوحدة `cqw` لا `px`** — استعمال البكسل يقصّ المحتوى على الجوال.
6. **شغّل `check.py` بعد كل تعديل.**

## ١٢) ما استجدّ بعد التسليم الأول

### أ) وحدة سجل الإجازات (جديدة كليًا)
مبنية على اللائحة التنفيذية للموارد البشرية في الخدمة المدنية:

- **١٣ نوع إجازة** بمواد اللائحة ومددها
- **احتساب المرضية بمراحلها**: ١٨٠ يومًا براتب كامل ← ١٨٠ بنصفه ← ٣٦٥ بربعه (والمرض الخطير: ٣٦٥ ← ١٨٠ ← ١٨٠)
- **الرصيد التراكمي للإجازة العادية** وفق المواد (١٣٠ · ١٣١ · ١٣٢): ٣٦ يومًا سنويًا، تسقط بعد ثلاث سنوات من نهاية سنة الاستحقاق، وسقف التمتع ١٠٨ أيام سنويًا (١٤٤ لمن تجاوز ٢٥ سنة خدمة أو ٥٠ عامًا)
- **ربط بالتقويم**: تنبيه قبل انتهاء الإجازة بثلاثة أيام وفي آخر يوم — مبنيّ على `S.reminders` و`scheduleNotifs` الموجودين
- **إشعارات نظام** للأرصدة التي قاربت النفاد
- **عرض التقويمين** هجري/ميلادي
- **كشف أرصدة** و**نموذج طلب إجازة** — طباعة وPDF وواتساب بتحذير خصوصية
- إخفاء حسب الجنس: الوضع والأمومة للمعلّمة، والأبوة للمعلّم

**الدمج:** اتبع `سجل-الإجازات-حزمة-الدمج.html` — التعديلات على كود قائم **ثلاثة مواضع فقط**.

**مسألة نظامية معلّقة:** المادة (١٤٠) تمنح الإجازة الاضطرارية لمن لا رصيد له من العادية. الوحدة تحتسبها **دون** هذا الشرط بقرار من صاحب المنتج.

### ب) ترتيب الصفحة الرئيسية (v2.7)
- عنوان موجّه: «ماذا تريد أن تنجز اليوم؟»
- بطاقة الإكمال تعرض **ثلاث خطوات قابلة للنقر** مرتّبة بالوزن، بدل تشخيص بلا علاج
- العشرون أداة مطوية خلف زر «🧰 كل الأدوات»
- الإعداد الأولي اختُصر لثلاثة حقول، والباقي تحت زر اختياري

### ج) خطوط ملف الأداء والشهادات
أربعة خطوط (Reem Kufi · Cairo · Tajawal · Amiri) عبر متغيّرات CSS — `--pf-head` و`--pf-body` و`--cert-font`.
**واجهة التطبيق لم تتغيّر** (هوية المنتج). خط الملف يُحفظ في `S.pfFont`، وخط الشهادة في `S.certFont`.

> **طلب:** عند الاستضافة داخل المملكة، استضف ملفات الخطوط معنا بدل جوجل — يلغي الاعتماد الخارجي ويسرّع التحميل.


### د) قرارات الاجتماعات — من المحضر إلى التنفيذ (v3.0)
تحوّل «سجل الاجتماعات» من أرشيف إلى أداة متابعة:

- **جدول قرارات لكل اجتماع**: نص القرار · المسؤول · الموعد · الحالة (لم يبدأ / قيد التنفيذ / منفّذ / متأخر تلقائيًا)
- **لوحة «قرارات لم تُغلق بعد»** أعلى الشاشة، تعدّ المتأخر وتعرض أقدم ستة
- **زر ترحيل**: ينشئ اجتماع متابعة وينقل القرارات المعلّقة إلى جدول أعماله
- **ربط كل قرار بأداة** (`MT_LINKS`): خطة علاجية · اختبار · تحليل نتائج · تعميم · شاهد مهني · تحضير — مع اقتراح تلقائي بالكلمات المفتاحية
- **محضر بالإملاء** (`mtToggleRec`): تسجيل صوتي عبر Web Speech API، ثم `mtExtract` يستخرج القرارات

> **مهم:** `mtExtract` يستدعي `aiCall`. عند فشله يعرض **تحذيرًا صريحًا** ويستخرج القرارات بالكلمات المفتاحية كبديل يدوي. لا يفشل بصمت.

### هـ) مساعد قرار الإجازة والمرفقات (v3.0)
- **`lvDecide()`**: عند اختيار النوع والتواريخ يعرض فورًا المدة والرصيد الحالي والمتبقي بعد الإجازة والمادة النظامية ومتطلب الموافقة، بحكم ملوّن (ضمن الرصيد / يستنفده / يتجاوزه)
- **`lvDoAll()`**: زر واحد يسجّل الإجازة وينشئ الطلب ويضيفها للتقويم
- **`lvAttach()`**: مرفقات لكل إجازة (تقرير طبي، إثبات اختبار) — صور تُصغَّر تلقائيًا وPDF
- **احتساب التجاوز**: كان `Math.max(0,...)` يبتلعه فتظهر ٩ أيام كأنها ٥. صُحّح ليعرض «تجاوز ٤ أيام»


### و) مساعد القرار — قبل وأثناء وبعد (v3.1)

**في الاجتماعات (`md_assist`):**
- `mdAgendaSuggestions()` يقرأ بيانات التطبيق — الطلاب المتعثرون والمتفوقون، العناصر بلا شواهد، القرارات المعلّقة، التعاميم، تنبيهات الإجازات — ويقترح بنود جدول الأعمال. **يعمل بلا ذكاء اصطناعي؛ حسابات لا توليد.**
- `MD_OPTIONS` يعرض بدائل لكل موقف مع **ميزة كل بديل وكلفته**، لا جوابًا واحدًا. اختيار بديل يضيفه قرارًا ويفتح أداته.
- `mdBuildAgenda()` يبني اجتماعًا جديدًا من البنود المحدَّدة.

**الربط الحقيقي بين القرار والأداة:**
- `mtGoLink` يمرّر السياق (أسماء المتعثرين للخطة العلاجية)، ويحوّل حالة القرار إلى «قيد التنفيذ»، ويعرض **شريطًا عائمًا** (`renderMtActive`) داخل الأداة.
- `mtFinishActive()` يغلق القرار، ويسجّل تاريخ التنفيذ، **ويضيف شاهدًا تلقائيًا** في عنصر الأداء المناسب عبر `mtEvidenceTarget`.
- خريطة الأدوات → عناصر الأداء: علاجية ← تحسين النتائج · اختبار ← تنويع التقويم · تحليل ← تحليل النتائج · تعميم ← المجتمع المهني · تحضير ← خطة التعلم.

**في الإجازات (`LV_GUIDE`):**
- مرشد **قبل** التسجيل: يختار المعلّم حالته (ظرف طارئ · مرض · إصابة عمل · اختبار · وفاة · ولادة…) فيُحدَّد النوع النظامي الصحيح، ويُعرض رصيده، **ويُطلب المستند المؤيد** المناسب (تقرير طبي، محضر إثبات إصابة، شهادة ميلاد…).
- ثم `lvDecide()` يعطي الحكم بعد التواريخ، و`lvDoAll()` ينفّذ الثلاثة بزر واحد.


### ز) من ملاحظات معلّمات مجرِّبات (v3.2)

**معاينة الشاهد** — طلب المعلمة هبة:
> «أدخل الشاهد يجيني حذف وتفاصيل… أنا أبغى أشوفه، يمكن أنا غلطانة؟ يمكن يحتاج تعديل؟»

`openEvPreview(i,j)` يعرض الشاهد **بشكله النهائي في صفحة الملف** — الشريط الكحلي واسم السجل ونص المتطلب والصورة — مع:
- **فحص نواقص** يسرد ما ينقص (وصف · صورة · سجل · تاريخ) ويشرح أثر كل ناقص
- زر **تعديل** يفتح تفاصيل الشاهد مباشرة
- تنقّل بين الشواهد داخل المعاينة نفسها

**توليد المحضر من العنوان** — طلب المعلمة حنين:
> «أعطيه عنوان وهو يولّد الباقي… ويكون عندي خيار تعديل متاح»

`mtAutoFill(i)` يأخذ موضوع الاجتماع فيولّد النوع والحضور وجدول الأعمال والقرارات والمهام بمسؤوليها — **وكلها حقول قابلة للتعديل**.
عند تعذّر الاتصال: `mtTemplateFrom()` يعبّئ هيكلًا جاهزًا مع تحذير صريح. **لا يفشل بصمت.**

**تحرير الشاهد كاملًا:** أُضيفت `setEvTitle` و`setEvDate` و`setEvType` و`replaceEvImg` و`removeEvImg` — كان التحرير مقصورًا على الوصف والأثر والتأمل، ولا يمكن تعديل العنوان أو التاريخ أو استبدال الصورة. وأُعيدت تسمية زر «تفاصيل» إلى **«✏️ تعديل»** لأن اللوحة كانت تحريرية والاسم يوحي بالعرض.

**ملفا عرض مستقلان:** `معاينة-الشاهد-عرض-حي.html` و`توليد-المحضر-عرض-حي.html` — الثاني فيه مفتاح لتعطيل المساعد واختبار البديل.


### ح) العمود الفقري — المبدأ الحاكم (v3.3 – v3.5)

> **لا يُدخل المعلّم المعلومة مرتين.** كل عمل داخل التطبيق يصير مصدرًا محتملًا لشاهد.

**١) محرك الشواهد `es_engine`** — ثمانية مصادر: الاجتماعات · قراراتها المنفَّذة · الأنشطة · التعاميم · الدروس · الرصد والخطط · رصد الإتقان · دورة التدخّل.
- `esScan()` يجمع الاقتراحات · `esCoverage()` يحسب قوة تغطية كل معيار
- **لا يضيف شاهدًا تلقائيًا** — كل اقتراح يحمل المعيار والمصدر وسبب الاقتراح، وأمامه «اعتماد» و«ليس مناسبًا»
- المرفوض يُحفظ في `S.evSuggest.dismissed` فلا يتكرر، ويمكن استرجاعه

**٢) رصد الإتقان `ms_engine`** — طبقة **مستقلة عن رصد الدرجات** لا تمسّه:
- المهارة تُشتقّ من أهداف الدرس المسجّل (`msSkillOf`)، وتُعدَّل يدويًا
- ثلاثة مستويات لكل طالب (متقن / قريب / غير متقن) في جولتين (قبلي / بعدي)
- `msMakePlan()` يستخرج من لم يتقن وينشئ خطة علاجية **ودورة تدخّل مربوطة**
- معرّفات ثابتة عبر `hashStr` فلا تختلّ عند حذف طالب أو درس

**٣) دورة التدخّل `iv_engine`** — تغلق الحلقة التي كانت مفتوحة:
- مساران للإنشاء: من رصد الإتقان (مربوط — يُقرأ القياس البعدي تلقائيًا من `msStats`) أو من تحليل النتائج (إدخال يدوي)
- متابعة: نوع التدخّل · الموعد · الحالة · **تمييز المتأخر تلقائيًا**
- `ivMeasure()` يسجّل القياس البعدي ويحسب التحسّن، ثم يتحوّل التدخّل إلى شاهد

**المسار الكامل:** درس → مهارة → رصد قبلي → اكتشاف غير المتقنين → تدخّل → رصد بعدي → مقارنة → **شاهدان في ملف الأداء** — بإدخال واحد.

**ملفات العرض:** `محرك-الشواهد` · `رصد-الإتقان` · `دورة-التدخل`

### ما لم يُبنَ بعد
- **اللجان** — `S.committees` فارغة ولا دالة إضافة. **وحدة جديدة لا تعميق.**
- **تقويم ما بعد الحصة** · **أثر النشاط والمرفقات** · **إجراء التعميم وحالته**


### ط) توحيد مسارات الشواهد (v3.6) — إصلاح معماري

**المشكلة:** كان في التطبيق **مساران** لإضافة الشاهد نفسه — مباشر (`ev.push` داخل القسم) وعبر المحرك. والأنشطة والتعاميم والتحضير والخطة العلاجية لها المساران معًا، فيمكن أن يظهر **شاهد مكرر** لأن الفحص كان بمطابقة العنوان والعنوانان مختلفان.

**الحل — وسم المصدر `_src`:**
- كل شاهد يُضاف تلقائيًا يحمل وسم مصدره: `act:bulk` · `prep:<lessonId>` · `circ:<i>` · `remedial:<class>` · `certs:bulk` · `radio:<date>` · `task:<mi>:<ti>` · ومعرّف الاقتراح عند الاعتماد
- `evHasSrc(id)` يفحص وجود الوسم · `evHasBulk(prefix)` يفحص التغطية بشاهد مُجمَّع
- `esScan()` يفلتر بالوسم أولًا، ثم بالتغطية المُجمَّعة، والعنوان احتياطًا أخيرًا
- `evAdd(stdName, ev, srcId)` — الطريق الموحّد لأي إضافة تلقائية مستقبلًا

**النتيجة المختبَرة:** أربعة اقتراحات → يُضاف شاهد الأنشطة المُجمَّع → يبقى اثنان (اختفى اقتراحا النشاط) → يُضاف شاهد تحضير فردي → صفر.

**ملاحظة للمطوّر:** أي مصدر جديد للشواهد **يجب** أن يمرّ عبر `evAdd` أو يحمل `_src`، وإلا عاد احتمال التكرار.

### ما زال غير متصل بالمحرك
اللجان (غير مبنية) · الميزانية · الخطة السنوية · تقييم المعلمين. والإجازات مستثناة عمدًا (بيانات صحية).


### ي) اكتشاف لا تصنيف (v3.7)

**كانت `aiClassifyEvidence` تصنّف وتضيف فورًا** — ذكاء اصطناعي يضع شاهدًا في معيار قد يكون خطأ، داخل وثيقة مهنية. صُحّح إلى:

**اكتشف → اقترح → اشرح السبب → المعلّم يعتمد → أضف**

- `showEvProposal()` يعرض بطاقة: عنوان الشاهد · المعيار المقترح · **سبب الاقتراح** («صنّفه المساعد الذكي» أو «صُنّف بمطابقة الكلمات المفتاحية — تعذّر الاتصال»)
- **قائمة لتغيير المعيار** إن كان الاقتراح خاطئًا
- `acceptEvProposal()` هو الوحيد الذي يضيف، ويضع وسم `aicls:*`
- زر «صنّف وأضِف» صار **«✨ اقترح المعيار»**

**ومصدران جديدان للمحرك (صار عشرة):**
- **التواصل مع أولياء الأمور** — يُقترح عند ٣ اتصالات موثّقة فأكثر، ويُوسم بـ`parent:<class>`
- **اللجان والمهام** — كل لجنة عضويةٌ موثّقة تُقترح لـ«التفاعل مع المجتمع المهني»، وكل مهمة منفَّذة لـ«أداء الواجبات الوظيفية»، والقوة تعلو بوجود الأثر أو المرفق


### ك) بعد الحصة: ماذا حدث؟ (v3.8) — آخر ميزة قبل الاختبار

كان التحضير ينتهي بطباعة الورقة. الآن ينتهي بتقويم يقود إلى إجراء:

- ثلاثة خيارات في بطاقة كل درس: **نُفّذت كما خُطط** · **بعض الطلاب لم يتقنوا** · **يحتاج إعادة أو تعزيز**
- عند الثاني: تُفتح قائمة طلاب الشعبة لاختيار من لم يتقن (`plOpenPicker`)
- ثم `plMakeIntervention()` ينشئ **دورة تدخّل** مربوطة بالدرس ومهارته
- ومصدر جديد للمحرك (`post:*`): الدرس المُقوَّم يُقترح شاهدًا — «تقويم بعد الحصة» لمعيار التحليل، أو «تنفيذ درس» لمعيار خطة التعلم

**المسار مكتمل:** تحضير → تنفيذ → تقويم → علاج → قياس → شاهد.

**مصادر المحرك صارت ١١.**


### ل) إعادة تسمية «تحضير الدروس» (v3.9) — من ملاحظة معلّمة

> «وش فايدة التحضير وهو أصلًا فيه في الوزارة برنامج؟»

اعتراض وجيه: منصة مدرستي فيها تحضير، والمعلّمة لن تحضّر مرتين. والاسم القديم كان يوحي بمنافسة المنصة الرسمية.

- **البطاقة:** «تحضير الدروس» ← **«التحضير والشاهد»**
- **عنوان الشاشة:** ← **«من التحضير إلى الشاهد»**
- **الوصف:** «حضّر هنا أو الصق تحضيرك من مدرستي — وملفّي يحوّله لشاهد منسّق، ويربطه بمهارة تقيسها قبل وبعد»
- **لوحة إرشاد** أعلى الشاشة تجيب السؤال مباشرة بثلاث فوائد: شاهد منسّق · مهارة تُقاس · تقويم يقود لإجراء — وتنتهي بـ«لا تحضّر مرتين: انسخ تحضيرك من مدرستي والصقه هنا»
- وُحّد الاسم في `TOOL_LABELS` وبقية المواضع

**وإصلاح خطأ كشفه الاستخدام:** `addPrepEvidence` كانت تفحص `S.lessons[0]` فقط، فتقول «ولّد تحضيرًا أولًا» حتى لو كان الدرس الثاني أو الثالث محضَّرًا. صُحّحت إلى `preparedLessons()` التي تفحص كل الدروس، ومع تعددها تعرض **قائمة اختيار** تبيّن المُضاف من قبل، وزر «أضف كل الدروس غير المُضافة».

**وخطآن كشفهما الاستخدام:**
- **`logAct` غير معرّفة** — كانت تُستدعى في **٥ مواضع** (التحضير · الشهادات · الأنشطة · الإذاعة · التعاميم) وتُسقط العملية بـ`ReferenceError`. عُرّفت كسجل نشاط خفيف في `S.actLog` بحد ٦٠ عنصرًا.
- **لا معاينة قبل التحويل لشاهد** — `prepEvFor` تعرض الآن الشاهد بشريط رأسه ومعياره ونوعه قبل الاعتماد، مع قائمة لتغيير المعيار، و`prepEvConfirm` هو الوحيد الذي يضيف.
- **الطريق المسدود عند التكرار** — كانت تُظهر «مُضاف من قبل» وتتوقف، فلا معاينة ولا مخرج. الآن **المعاينة تظهر دائمًا**، ومعها تنبيه ومخرجان: `prepEvGoto()` يفتح الشاهد الموجود في ملف الأداء، و`prepEvRedo()` يحذف القديم ويعيد الإنشاء بتأكيد. والدروس المُضافة في القائمة صارت **قابلة للنقر** بدل تعطيلها.

- **التحذير يحجب الشاهد** — كانت الملاحظات والمعاينة في شاشة واحدة، فيأخذ التحذير نصفها وينضغط الشاهد. صارت **تبويبين**: «👁️ معاينة الشاهد» (افتراضي) و«📋 الملاحظات» بعدّاد النواقص. وصفحة الملاحظات تعرض جدول الحقول كاملًا مع تمييز الناقص بالأحمر.

- **الشاهد النصّي كان يُوسم ناقصًا** — «تنفيذ قرار» و«محضر اجتماع» شواهد نصّية بطبيعتها، ولا صورة لها ولا سجل، فكان التطبيق يشعر المعلّم بالإجبار على ما لا يملكه. فُصل النقص إلى **مطلوب** (الوصف والتاريخ — يظهران في رأس الصفحة) و**مقترح** (الصورة والسجل — بصياغة «لست ملزمًا به»). وأُضيف زر **«✓ أعتمده كما هو»** (`evpApprove`) يحفظ `_ok` على الشاهد فتُخفى الملاحظات، مع تراجع متاح. والشواهد التي يولّدها التطبيق نفسه تُحفظ معتمَدة سلفًا.

- **زر الاعتماد كان مخفيًا** — وُضع داخل تبويب «الملاحظات»، و`openEvPreview` تفتح دائمًا على «المعاينة»، فالتنقّل بالسابق/التالي لا يُظهره أبدًا. أُضيف **شريط اعتماد ثابت** (`#evp-approve-bar`) فوق أزرار التنقّل، ظاهر في التبويبين، يعرض حالة الشاهد وزر الاعتماد أو التراجع.
- **بعد الاعتماد**: شاشة تأكيد بزر «التالي ←» ينتقل لأول شاهد غير معتمد (يتخطى المعتمَد)، وزر «إغلاق»، وإغلاق تلقائي إن اعتُمد الجميع.

**قاعدة تصميم عامة:** لا تُلزم المستخدم بما ليس لازمًا، وأعطه دائمًا مخرجًا يتحمّل مسؤوليته.

**درس:** التبويب لم يكن مكررًا — كان **وصفه** يوحي بالتكرار. الاسم يصنع الانطباع الأول.


### م) سجل الطالب الموحّد (v4.0)

صفحة **قراءة محضة** — لا إدخال جديد فيها إطلاقًا. تجمع ما هو مُدخل أصلًا في أقسام متفرقة:

| المصدر | ما يُقرأ منه |
|---|---|
| `s.scores` | الدرجات عبر الفترات + الاتجاه (متحسّن / مستقر / متراجع) |
| `S.mastery` | المهارات قبلي/بعدي لكل درس |
| `s.abs` | الغياب موزّعًا على الفترات |
| `S.interventions` | التدخّلات ونتائج قياسها |
| `s.contacts` | سجل التواصل مع الأسرة |
| `l.post.weak` | دروس لم يتقنها في تقويم ما بعد الحصة |

- `srStatus()` يشخّص الطالب من كل ذلك: **🔴 يحتاج تدخّلًا · 🟠 يحتاج متابعة · 🟢 مستقر** — مع سبب صريح لكل حكم مبني على `S.thresholds`.

**وحقل «↩ ماذا ستفعل الحصة القادمة؟»** أُضيف لتقويم ما بعد الحصة (`plSetNext`)، وتظهر آخر ملاحظتين أعلى شاشة التحضير عبر `plPrevNotes()` — فيصير التحضير حلقة متصلة لا مستندًا منفصلًا.

**ملف العرض:** `demos/سجل-الطالب-عرض-حي.html`


### ن) ترويسة المستندات والتقويم الدراسي (v4.0)

**الترويسة أُعيد بناؤها — كان فيها تكرار ثلاثي:**
- «المرحلة: المتوسطة» ثم «الصف: الثالث المتوسط» — والصف يتضمّن المرحلة
- «الفصل الدراسي: الفصل الدراسي الثاني» — المسمّى مكرر في قيمته
- «المدرسة: متوسطة الأمير سلطان» — يكفي الاسم

**الشكل المعتمد الآن** — عمودان (`eduAuthority` · `docYear`):
```
المملكة العربية السعودية              الصف الثالث المتوسط
وزارة التعليم                          الفصل الدراسي الثاني
الإدارة العامة للتعليم بمحافظة الطائف   العام الدراسي ١٤٤٨هـ
متوسطة الأمير سلطان
──────────────────────────────────────────────────
```
اليمين: الجهة · اليسار: سياق المستند · الوسط: الشعار. و**`stageValue` لم تعد تُستعمل في الترويسة** — المرحلة محذوفة لأن الصف يتضمّنها.

**وتكرار ثالث + تناقض في التحضير اليومي:** السطر كان يعرض `fmtDate(اليوم)` والجدول يعرض `weekDate(1)` — **تاريخان مختلفان لدرس واحد** (٩ ربيع الأول مقابل ١٧ شعبان). أُضيفت `lessonDate(l,idx)` كمصدر وحيد: تاريخ الدرس إن وُجد، وإلا تاريخ أسبوعه المحسوب من `S.startDate` و`S.weeks`، وإلا اليوم. وأُزيل تكرار العنوان والمادة بين السطر والجدول.

**وتكرار ثانٍ في ٢١ موضعًا:** أسطر `doc-meta` تحت عنوان كل مستند كانت تعيد المدرسة والصف والفصل والعام — وكلها في الرأس. نُظّفت فصار كل سطر يحمل ما يخصّ مستنده: «الرياضيات · جمع الكسور · ٩ ربيع الأول ١٤٤٨هـ».
- **التقويم الدراسي `ACADEMIC_CAL`** — **مرجع زمني داخلي لا يُعرض في المستندات.** يبني عليه البرنامج:
  - `applyTermDefaults()` يملأ `S.startDate` تلقائيًا ببداية الفصل الجاري
  - `termWeeks()` يحسب عدد أسابيع الفصل من الفرق بين تاريخي البداية والنهاية (الأول ٢١ أسبوعًا · الثاني ٢٠)
  - `currentTerm()` يعرف الفصل الجاري من `S.term` أو من التاريخ الفعلي
  - `weekDate()` تبني عليه تواريخ أسابيع توزيع المنهج
  - `termCalCard()` بطاقة في شاشة التحضير تعرض الفصلين وتبيّن ما بُني عليها، وفيها زر «أعد الضبط من التقويم»
  - **التواريخ:** الأول ٣/٣/١٤٤٨ → ٢٩/٧/١٤٤٨ · الثاني ٩/٨/١٤٤٨ → ١٩/١/١٤٤٩
  - **وخيارات «عدد الأسابيع» كانت ثابتة (١٣ · ١٥ · ١٧)** ولا تحوي القيمة الصحيحة أصلًا. صارت تُبنى من التقويم عبر `weeksOptions()`: الفصل الأول **٢١ ✓** والثاني **٢٠ ✓** مع بدائل قريبة، والقيمة المحسوبة مميّزة بعلامة، وتحتها تلميح وزر ضبط سريع.
  - وأُصلح `setWeeks` — كان يمسح التحديد من **كل** المنتقيات في شاشة التحضير لا من منتقي الأسابيع وحده.
  - **للمطوّر:** كل عام دراسي يحتاج مدخلًا جديدًا في `ACADEMIC_CAL` بالهجري والميلادي معًا (الميلادي للحساب).
- **قائمة «المزيد»** — أُضيف `⬇️ نزّل نسخة احتياطية` و`⬆️ استرجع من نسخة` (`restoreBackup` جديدة، تتحقق من صحة الملف وتعرض عدد الطلاب والشواهد وتطلب تأكيدًا قبل الاستبدال)، مع فواصل بعناوين.
  - **«حسابي والمزامنة» و«الاشتراك»** أُضيفا للقائمة عبر موجّهين: `openAccountSync()` و`openSubscribeScreen()`.
    كل واحد يبحث عن دالتك (`openAccount` · `openSync` · `openCloud` · `openSubscribe` · `openSubscription` · `openBilling` · `openPlan`) ويستدعيها إن وُجدت.
    **وإن لم توجد، لا يفشل صامتًا** — بل يخبر المستخدم أن الشاشة تُدار من الخادم ولم تُفعَّل بعد، ويعرض عليه تنزيل نسخة احتياطية.
    **المطلوب منك:** سمِّ دالتك بأحد تلك الأسماء، أو عدّل قائمة البحث في الموجّه — فتعمل الأزرار تلقائيًا بلا تعديل آخر.


### س) بناء الاختبار بالدرجات وجدول المواصفات (v4.1)

**١) الاختبار يُبنى بالدرجات لا بعدد الأسئلة.** المعلّم يحدّد الدرجة الكلية (٢٠ مثلًا) ويوزّعها على الأنواع، و`bpSum()` يتحقق حسابيًا: «✅ المجموع مطابق ٢٠ · ١٢ سؤالًا» أو «⚠️ ينقص ٤ درجات». وزر «⚖️ وزّع الدرجات تلقائيًا» يقترح توزيعًا يساوي المجموع. **يعمل بلا وسيط — حساب لا توليد.**

**٢) جدول المواصفات يتكيّف مع المادة** (`BLUEPRINTS` · `bpFor`):

| المادة | المحاور | أنواع الأسئلة |
|---|---|---|
| الرياضيات | مفاهيم ٢٠٪ · تطبيق ٤٠٪ · حل مسائل ٣٠٪ · تفكير أعلى ١٠٪ | + **حل مسألة** · **أظهر خطوات الحل** |
| English | Vocabulary ٢٥٪ · Grammar ٢٥٪ · Reading ٣٠٪ · Writing ٢٠٪ | Multiple Choice · Matching · Writing |
| العلوم | تذكر ٣٠٪ · تطبيق ٤٠٪ · تحليل ٢٠٪ · تفكير أعلى ١٠٪ | الأنواع العامة |
| غيرها | تذكر ٣٠٪ · تطبيق ٥٠٪ · تفكير أعلى ٢٠٪ | الأنواع العامة |

و`bpPromptBlock()` يُدخل المواصفات في موجّه التوليد، ومنها تعليمات خاصة: الرياضيات تطلب **خطوات الحل في نموذج الإجابة**، والإنجليزي يبني أسئلة Reading على القطعة إن وُجدت.

**٣) تحرير السؤال بعينه** — `qRegen(i,mode)` بثلاثة أزرار: **🔄 أعد توليده · ↓ أسهل · ↑ أصعب**. لا يعيد توليد الاختبار كله.
> **عند تعذّر الاتصال:** رسالة صريحة تخبر المعلّم أن الحقول أمامه قابلة للتحرير يدويًا، وتعرض حذف السؤال بدلًا من ذلك. **لا فشل صامت.**

**٤) ربط النتائج بالتحليل** — جدول المواصفات يحفظ **الدرس/المهارة المستهدفة**، و`examToAnalysis()` ينقل مباشرة إلى رصد الإتقان في الجولة البعدية لذلك الدرس — فمن لم يتقن يُقترح له تدخّل. وملخص بعد التوليد: «١٢ سؤالًا · ٢٠ درجة · ٤ سهل · ٦ متوسط · ٢ متقدم».

**ملف العرض:** `demos/جدول-المواصفات-عرض-حي.html` — فيه مبدّل مادة ومفتاح لتعطيل المساعد واختبار البديل.


### ع) أوزان الدروس · تشخيصي · نموذج أ/ب · أسئلة محفوظة (v4.2)

**١) وزن كل درس** (`lwSet` · `renderLessonWeights`) — عند اختيار دروس للاختبار يحدّد المعلّم نسبة كل درس (الكسور ٤٠٪ · النسبة ٣٥٪ · الإحصاء ٢٥٪)، مع **تحقق حسابي من ١٠٠٪** وزر توزيع بالتساوي. و`lwPromptBlock()` يُدخلها في موجّه التوليد. **التحقق يعمل بلا وسيط.**

**٢) اختبار تشخيصي** (`setExamKind`) — خياران عند الإنشاء: عادي / تشخيصي.
- في التشخيصي يظهر بجانب كل سؤال منتقي مهارة، **يُملأ تلقائيًا من الدرس** (`qSkillOf`) فلا يصير عبئًا
- `diagAnalyze()` يبني خريطة: «جمع الكسور: ٤ أسئلة · ٨ درجات»، ثم ينقل لرصد النتائج فيُقترح تدخّل لمن أخفق

**٣) نموذج أ / ب** (`examVariant` · `shuffled`) — **يعمل بلا وسيط.** نفس المحتوى والدرجات، وترتيب الأسئلة والخيارات مختلف، **والإجابة الصحيحة تتبع خيارها** (`correctIdx` يُعاد حسابه). الخلط بمولّد عشوائي ببذرة ثابتة فالنموذج (ب) نفسه في كل مرة.

**وثلاثة إصلاحات من الاستخدام:**
- **أمثلة استرشادية** (`EX_SAMPLES`) تحت كل نوع سؤال في جدول المواصفات — «مثال: ما ناتج ٣/٧ + ٢/٧ ؟» — فيفهم المعلّم ما يوزّع درجاته عليه. ومع الصفر يظهر اقتراح: «مثال: ٦ = ٣ أسئلة × ٢».
- **خيارات الاختيار من متعدد** كانت في سطر واحد بفواصل `&nbsp;` فتنزاح وتتكسر. صارت **شبكة عمودين** بدوائر مرقّمة بالحروف، ومع `print-color-adjust:exact` لتظهر في الطباعة.
- **عرض الورقة والإجابة معًا** — تبويب ثالث «🔀 الاثنان معًا» يعرضهما جنبًا إلى جنب (`doc-split`)، وفي الطباعة كل واحد في صفحة.

**وإصلاح محرر الخيارات على الجوال — أولوية قبل الإطلاق:**
> المعلّم كان يظن أن المولّد فشل في توليد الخيارات، **والخيارات مولَّدة فعلًا** — الخلل في العرض وحده.

**السبب التقني:** حقل نص الخيار داخل `flex` بلا `min-width:0`. وحقول `input` لا تنكمش تحت عرضها الافتراضي داخل flex، فتدفع الصف وتكسره على الشاشات الضيقة — فيظهر مربع منزاح والراديو في المنتصف والنص شبه مختفٍ.

**الإصلاح:**
- الصف صار **بطاقة واحدة**: `radio` + حرف الخيار (أ/ب/ج/د) + حقل النص + 🗑️ حذف — في سطر واحد بعرض الشاشة
- `.opt-t{flex:1;min-width:0}` — الحل الجوهري
- الخيار الصحيح **مميّز بالإطار والخلفية** وحرفه بالأخضر
- `delOption()` بحد أدنى خيارين وأقصى ستة، و`correctIdx` يُعاد ضبطه بعد الحذف
- الافتراضي **٤ خيارات** (كان يستورد حتى ٦)
- حقل السؤال `rows="2"` مع `autoGrow()` — يبدأ صغيرًا ويتمدد مع النص
- **وتصحيح لاحق:** أول إصلاح جعل كل خيار **بطاقة** بإطار وحشو، فصار «نموذجًا مستقلًا» يستهلك مساحة ضخمة على الجوال. أُعيد إلى **سطر أفقي مضغوط**: `◯ | أ | [نص الخيار] | 🗑️` بلا إطار ولا خلفية، والتمييز بلون الحقل وحده.

**والمزاوجة كانت مقصوصة فعليًا — نفس العلّة:** حقلان `flex:1` بلا `min-width:0` فالثاني يخرج عن الإطار.
- `.pair-a{flex:0 0 45%}` و`.pair-b{flex:1;min-width:0}` مع `word-break:break-word`
- **وعلى الشاشات دون ٥٢٠px تتراصّ**: العمود أ في سطر، ثم سهم ↔ مُدار، ثم العمود ب في سطر كامل — بدل عمودين متجاورين مضغوطين

**قاعدة للمطوّر:** أي `input` داخل `flex` يحتاج `min-width:0` — وإلا لا ينكمش تحت عرضه الافتراضي فيكسر الصف. تكرّرت هذه العلّة في موضعين.

**٤) الأسئلة المحفوظة** (`qSave` · `qInsert`) — **يعمل بلا وسيط.** زر ☆/⭐ بجانب كل سؤال، و«⭐ أسئلتي المحفوظة» يعرض المحفوظ في المادة نفسها مع إدراج بضغطة. حد أقصى ٣٠٠ سؤال في `S.savedQuestions`.

اقتُرح قسم «نصائح وإرشادات» في آخر الصفحة، ورُفض: **النصيحة تُقرأ حين ترتبط بلحظتها**، أما المجموعة في مكان قصيّ فلا تُقرأ. فبُنيت نصيحتان تظهران بشروط:

**مغلق افتراضيًا** بناءً على ملاحظة صاحب المنتج: بعض المعلمين يسلّمون الملف رسميًا وتاريخ التوليد قد يوحي بأنه أُعدّ متأخرًا. الخيار في شريط المظهر مع الألوان والخطوط.

4. **خانة التوقيع** — كانت «المشرف» وحدها. صارت `docApprovers()` تقرأ `S.docApprover`، وخيارها في الهوية المهنية: مدير المدرسة / المشرف التربوي / كلاهما.

⚠️ **ما لم يُصلَح ويحتاجك:**
- `fallbackLesson()` ما زالت تركّب عنوان الدرس في قوالب ثابتة. رسالة الفشل صارت صريحة (v4.3)، لكن القالب نفسه باقٍ. الحل الصحيح: تمرير **نص الدرس كاملًا** في الـprompt، لا عنوانه فقط.

- **سجل الرصد:** عمود الغياب لا يُوضَّح هل يُخصم، وحدود التقدير غير مطابقة لسلّم الوزارة موثّقًا.

**🎛️ غرفة القرار — مدخل لا نسخة (v4.3):**
لوحة المؤسس **لم تُدمج** في التطبيق، وأُضيف بدلها بند في «المزيد» يفتح `FOUNDER_ROOM_URL` في المتصفح.

**سبب الرفض بالأرقام:** اللوحة فيها `go()` و`fmtDate()` بأسماء التطبيق نفسها بمعانٍ مختلفة، و**١٦ صنف CSS متصادمًا** (`card`,`chip`,`note`,`num`,`on`…). والأهم: فيها `createClient` ومفاتيح Supabase — دمجها يشحن مفاتيح قاعدة البيانات إلى جهاز كل معلّمة، ويُقرأ بـ«عرض المصدر». كما أن `MODE='demo'` يعني أرقامًا ملفّقة داخل التطبيق.

> ⚠️ **الإخفاء يمنع الفضول لا الاختراق.** الحماية الحقيقية تسجيل دخول على الخادم أمام `/room`، ولا بديل عنه. ارفع اللوحة خلف Auth قبل أن تحمل بيانات إنتاج.

**🎨 تصاميم الغلاف — استُعيدت في v4.3:**
كانت في v2.5 ثلاثة تصاميم (أمواج · هندسي · إطار كلاسيكي) واختفى مبدّلها بين v2.5 وv4.3، فبقي `pfWave()` وحده يرسم الأمواج ولا سبيل لتغييرها.

الآن `pfWave()` موزّع: `pfDesignWaves` / `pfDesignGeo` / `pfDesignFrame`، وكلها SVG بمتغيّرات اللون نفسها (`--pf-w1..w4`) فتتبع «هوية الملف» تلقائيًا.

**وأُضيف تصميم خاص:** رفع صورة → `shrinkImage(1400, .85)` → `S.pfCoverImg`. إن امتلأت المساحة تُلغى ولا تُحفظ نصفًا. والتبديل يستبدل عنصر `.pf-wave` في مكانه بدل إعادة توليد الوثيقة — فلا يُعيد التنقّل ولا يُطلق إشعارًا.

⚠️ الصورة المرفوعة تُخزَّن في `localStorage` كباقي البيانات، وتدخل النسخة الاحتياطية. ذكّر المعلّم بأن غلافًا ثقيلًا يقتطع من مساحة شواهده.

**📄 التقارير + مولّد الباركود (v4.3) — من ملاحظات معلّمين حقيقيين:**
الشكوى: «نسوّي باركود برا، وتقرير برا، ونرجع نضيفه في البرنامج» — ثلاث أدوات لعمل واحد.

- **مولّد QR مكتوب من الصفر** (ISO/IEC 18004، نمط بايت، تصحيح M، النسخ ١–١٥). بلا مكتبات وبلا إنترنت. `qrGenerate(text)` يعيد مصفوفة، و`qrDataUrl(text,px)` صورة PNG.
- **تحقُّق:** كُتب فاكّ ترميز مستقل واختُبرت ١٢ حالة (عربي وإنجليزي، النسخ ١–١٥) — كلها ذهبت وعادت مطابقة ومتلازمات Reed-Solomon صفر. ثم أُعيد الاختبار على المولّد **بعد حقنه في التطبيق**.
- **أداة «التقارير»** مستقلة في «كل الأدوات»: عنوان + قالب سبعة حقول + «أضف حقلًا» + رابط درايف → رمز واحد لكل تقرير + طباعة/PDF/Word + «أضفه شاهدًا».

> **الصور لا تُخزَّن في التطبيق إطلاقًا.** ترفعها المعلّمة على درايفها، والتقرير يحمل الرمز. هذا يحلّ مشكلة حصة `localStorage` التي كانت تهدّد التطبيق مع خمسين صورة لكل نشاط.

⚠️ **ما زال يحتاجك:**
- **`rptGenerate()` يستدعي `aiCall`** — «ولّد المحتوى من العنوان» هو أهم ما طلبته المعلّمات، ولن يعمل قبل الوسيط. يفشل صراحةً بلا قالب بديل.
- **الرفع إلى درايف المعلّمة** يحتاج OAuth وخادمًا. الحالي: ترفع يدويًا وتلصق الرابط.
- **صلاحية المشاركة:** رمز يشير إلى مجلد «مقيّد» لن يفتحه المشرف. ويجب تنبيه المعلّمة أن مجلدًا فيه صور طالبات بمشاركة «أي شخص لديه الرابط» يصير مفتوحًا لكل من يمسك الورقة — قرار خصوصية يخصّ قاصرين.

**☁️ الرفع إلى درايف المعلّم — بنية جاهزة، ينقصها التوصيل:**
الواجهة والعقد مبنيان. ضع مسارك في `DRIVE_ENDPOINT` فتعمل الأزرار بلا تعديل آخر.

```
POST {DRIVE_ENDPOINT}   ·   FormData
  files[]     الملفات (صور/فيديو)
  folderName  اسم المجلد المقترح (عنوان التقرير)
  reportId    معرّف التقرير — لإعادة الرفع إلى المجلد نفسه
→ { folderUrl:"…", count:47, shared:true }
```

**خمسة شروط على الخادم:**
1. رمز OAuth للمعلّم (`drive.file`) يُحفظ عندك لا في المتصفح.
2. ينشئ المجلد إن لم يوجد، ويعيد استعماله عند الرفع الثاني لنفس `reportId`.
3. **يضبط الصلاحية «أي شخص لديه الرابط — قارئ».** وإن تعذّر يعيد `shared:false`، والتطبيق ينبّه المعلّم صراحةً — لأن رمزًا يشير إلى مجلد مقيّد يعطي المشرف «طلب إذن».
4. الملفات تمرّ ولا تُخزَّن على خادمك.
5. **لا تعود الملفات إلى التطبيق إطلاقًا — الرابط فقط.** هذا ما يحمي حصة `localStorage`.

الحدّ الحالي `DRIVE_MAX_MB=25` لكل ملف، يُفحص في المتصفح قبل الإرسال.

**🔤 خطوط الوثائق — تضمين مطلوب منك:**
`DOC_FONTS` فيه تسعة خطوط، **ثلاثة منها نظامية** (معلَّمة بـ◆ في الواجهة):

|---|---|---|

**المطلوب: تضمينها محليًّا بـ`@font-face`** لتظهر على الجوال أيضًا:

```css
@font-face{font-family:'Sakkal Majalla';src:url('/fonts/majalla.woff2') format('woff2');

@font-face{font-family:'Sakkal Majalla';src:url('/fonts/majallab.woff2') format('woff2');

```
وكذلك `Simplified Arabic` و`Adobe Arabic`. الأسماء في `src` هي ما تُطابق `font-family` في السلسلة — لا تغيّرها.

⚠️ **الترخيص مسؤوليتك:** الثلاثة ليست حرة. Sakkal Majalla وSimplified Arabic تُرخَّصان مع Windows/Office، وAdobe Arabic من Adobe. تضمينها في موقع عام يحتاج ترخيص توزيع ويب — راجع ذلك قبل الرفع، أو اكتفِ بسلوكها الحالي (Word نعم، الجوال بديل).

**والمطلوب أيضًا: تضمين الخطوط الحالية محليًّا** بدل تحميلها من Google — Reem Kufi وIBM Plex وCairo وTajawal وAmiri وNoto Naskh. بلا ذلك:
